# Query-Dependent Passage Granularity

This repository contains the code, frozen configuration, experiment outputs, and reports for the project **“Query-Dependent Passage Granularity: Can a Router Choose the Right Chunk Size per Query?”**

## Project overview

The project studies whether a retrieval system can select an appropriate passage granularity for each query. It evaluates six granularities:

- Sentence
- 128-word windows (`p128`)
- 256-word windows (`p256`)
- 512-word windows (`p512`)
- Paragraph
- Section

The experiments use BM25 retrieval over the paper associated with each QASPER question and evaluate matched context budgets of 256, 512, and 1,024 whitespace-separated words. The main evaluation metric is evidence coverage; evidence hit recall is also reported.

## Requirements

- Python 3.10 or later
- Dependencies listed in `requirements.txt`

Install dependencies:

```bash
python -m pip install -r requirements.txt
```

## Run using the included caches

Run commands from the project root.

Run the fixed-granularity evaluation:

```bash
python src/exp1.py
```

Run the additional router experiments:

```bash
python src/exp2.py
python src/exp3.py
python src/exp4.py
```

Run the frozen main evaluation:

```bash
python src/route.py test
```

`config.json` contains the hyperparameter choices selected on the development split. Keep this file unchanged when reproducing the reported held-out test evaluation. The test evaluation was intended to be run once with the frozen configuration.

## Rebuild caches from QASPER

To regenerate the caches, obtain the QASPER v0.3 dataset through its official distribution and place these files in a `data/` directory at the project root:

```text
data/
├── qasper-train-v0.3.json
├── qasper-dev-v0.3.json
└── qasper-test-v0.3.json
```

Then run:

```bash
python src/build.py
```

This generates `cache_train.pkl`, `cache_dev.pkl`, `cache_test.pkl`, and `lsa.pkl` in the project root. The build script expects the `data/` directory and these exact filenames. `lsa.pkl` is an intermediate artifact generated by the build script; the routing scripts do not load it directly.

To retune the router on the development split, run:

```bash
python src/route.py dev
```

This rewrites `config.json`. Only do this when intentionally creating a new experiment configuration; do not do it before reproducing the submitted frozen test results.

## Results

- `results/results_test.csv`: main test results across systems and word budgets, including confidence intervals and latency fields.
- `results/results_slices_B512.csv`: results broken down by answer type at the 512-word budget.
- `results/results_detail.json`: routing choice counts and dataset summary information.
- `results/error_analysis.json`: selected high-regret examples.
- `results/experiment*_results.json`: outputs from the additional experiment scripts.
- `figures/fig_main.png`: main results figure.

See `docs/Final_Report.pdf` and `docs/Final_Paper.pdf` for the written discussion. `docs/PILOT_REPORT.md` contains supplementary experiment notes.

## Notes

- The scripts use QASPER v0.3 JSON files when rebuilding caches. The dataset itself is not bundled here.
- The caches are Python pickle files. Load them only from a trusted project source.
- Timings are environment-dependent and may differ across machines.

## Regenerate the main figure

```bash
python plot_results.py

```

It reads `results/results_test.csv` and writes `figures/fig_main.png`.
